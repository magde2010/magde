# Lotfe — MEXC Spot Bot

بوت إدارة محافظ MEXC بنظام يدوي فقط، مع تقرير حالة سوق شامل للقراءة والتحليل.

## إدارة المحافظ

- TP1 وTP2 ونسب البيع ووقف الخسارة يحددها المستخدم.
- لا يوجد وضع تداول ذكي أو شراء تلقائي للحيتان.
- بعد TP1 وTP2 يبقى الجزء المتبقي تحت قواعد الاستوب اليدوي وإعادة الدخول المحددة.
- إعادة بناء المراكز تطبق إعدادات المحفظة اليدوية وتحافظ على سجلات المحافظ والصفقات.

## تقرير حالة السوق

زر **تقرير حالة السوق** يعرض:

- حركة BTC على أطر الساعة و4 ساعات و24 ساعة تقريباً.
- تصنيف حالة السوق ونطاق الحركة.
- عدد العملات الصاعدة والهابطة والهادئة داخل المحافظ.
- قيمة المراكز والربح/الخسارة غير المحققة تقريبياً.
- معلومات رادار الحيتان للقراءة فقط، دون تنفيذ أي تداول.

## اصطياد الهبوط

- يدوي: تحديد مستويات السلم وميزانيته.
- تلقائي: اختيار مستويات السلم من حركة BTC/ETH فقط، دون دفتر أوامر.

## البيانات

تم الحفاظ على قاعدة البيانات والجداول والسجلات الحالية. تم توحيد `control_mode` للمحافظ إلى `manual` دون حذف المحافظ أو الصفقات أو سجل الأحداث.

## البيئة

`TELEGRAM_BOT_TOKEN`, `MEXC_API_KEY`, `MEXC_API_SECRET`, `DATABASE_URL`, `ADMIN_TELEGRAM_ID`

على Railway يجب ربط خدمة البوت بخدمة PostgreSQL داخل **نفس المشروع والبيئة**، ثم ضبط
`DATABASE_URL` كمرجع لمتغير قاعدة البيانات، مثل:

```text
${{Postgres.DATABASE_URL}}
```

إذا ظهر الخطأ `could not translate host name ... railway.internal`، فالعنوان الداخلي
غير قابل للحل من الخدمة الحالية. صحّح مرجع `DATABASE_URL` أو أضف `DATABASE_PUBLIC_URL`
كرابط PostgreSQL العام من خدمة قاعدة البيانات؛ التطبيق يستخدمه تلقائيًا عند اكتشاف عنوان
داخلي غير صالح.

## ₿ BTC Risk Governor — V4

بدل نظام الحماية المعقد السابق، LOTFE يستخدم BTC كمؤشر مركزي لإدارة **المخاطرة الجديدة** لكل المحافظ.

- مؤشر BTC من `0..100`.
- `80–100` قوي: دخول جديد بالحجم الكامل.
- `65–79` صحي: مخاطرة مرتفعة.
- `45–64` حذر: تصغير حجم الدخول.
- `25–44` دفاعي: تصغير قوي.
- `0–24` خطر: لا يتم فتح مراكز جديدة.
- التعافي تدريجي؛ لا يعود البوت إلى 100% مخاطرة بمجرد شمعة خضراء.
- النظام **لا يجبر المحافظ على البيع** ولا يلغي أوامر TP ولا يقوم بخروج طوارئ؛ BTC يتحكم فقط في حجم الشراء الجديد.
- كل مسارات الشراء تمر عبر `MexcClient`، لذلك Sniper / SuperTrend / CPR / Re-entry / Rebuild / Crash Hunter تخضع لنفس ميزانية المخاطرة.

الإعدادات موجودة في `.env.example`.


## التنفيذ التلقائي لمخاطر BTC على المراكز المفتوحة

بالإضافة إلى تخفيض المشتريات الجديدة، يراقب البوت مؤشر BTC كل 30 ثانية ويطبق المخاطر بالتساوي على كل المراكز المفتوحة:

- مستوى 0 قوي: يحتفظ بـ 100% من المركز.
- مستوى 1 صحي: يحتفظ بـ 100% من المركز.
- مستوى 2 حذر: يخفض المركز إلى 80%.
- مستوى 3 دفاعي: يخفض المركز إلى 50%.
- مستوى 4 خطر أو بيانات متأخرة: يخفض المركز إلى 20% ويوقف الدخول الجديد.

يتم إلغاء أوامر TP للمركز قبل التخفيض، ثم تسجل العملية في سجل التداول. عند تعافي BTC، يعيد البوت شراء الكمية الناقصة تدريجيًا عند عودة المؤشر إلى مستويات 25 ثم 45 ثم 65 ثم 80، مع تهدئة افتراضية 30 دقيقة بين العمليات. لا يتم بيع كل المراكز دفعة واحدة، بل يتم التخفيض بالتساوي لكل مركز.
